# What is w6w

w6w is central API management. Every API a product runs on — the ones it owns and the ones it
buys — is managed in one place. The unit being managed is an **API**: not a workflow, not a
credential.

## Four pillars

1. **One front door.** Call many APIs through a single access point with a single credential.
2. **Composition.** Endpoints, Functions and Workflows for when one call isn't enough.
3. **Visibility.** Performance and health across first-party and third-party APIs alike.
4. **Plug and play.** Change what's underneath your backend automation without shipping code.

Workflows are one way to compose several APIs. Connections are how one authenticates. Health is
whether it works. Variables, secrets and documents configure it, and tenancy owns it.
